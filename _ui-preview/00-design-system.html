Premisas, tokens y componentes para la sección Estimates (extensible a todo el dashboard)

① Lista ② Detalle ③ Form New/Edit ④ Print

Filosofía

SaaS profesional. Navy + Orange. Densa pero respirable.

El sistema actual ya tiene buenos cimientos (tokens --wp-*, paleta navy/orange, componentes .btn-*, .badge-*). La propuesta no tira nada — extiende, unifica y pule. Pasamos de un dashboard funcional a uno con jerarquía visual profesional estilo Stripe/Linear/Vercel, manteniendo la personalidad de contractor que ya tienes.

Problemas detectados en el código actual

  • !
    Inline styles inconsistentes. Convive style={{ color: 'var(--wp-primary)' }} con className="text-[#1E3A5F]" y text-slate-700. Esto hace imposible cambiar la paleta de golpe.
  • !
    Toggle switch duplicado 5+ veces en EstimateFormClient con lógica copy-paste. Debe ser un componente <Toggle/>.
  • !
    Tipografía microgestionada en inline — valores como 0.6875rem, 0.8125rem, 0.9375rem repartidos por todo el código. Falta una escala tipográfica clara.
  • !
    Action bar del detalle es una fila larga de botones que compiten entre sí (6 botones al mismo peso visual).
  • !
    No hay affordance en la tabla del listado — filas clickeables sin hint visual. Tampoco hay quick actions al hover.
  • !
    Sin timeline de actividad visible. La info de "visto 3 veces" es un chip pequeño perdido en el header.
  • !
    KPIs faltantes — la vista listado muestra una barra de progreso oculta hasta aplicar filtro, en lugar de dar un dashboard de 4 métricas al tope.

Qué cambia por vista (resumen ejecutivo)

① Lista de Estimates

  • +
    Dashboard KPI row con 4 tarjetas (Pending, Approved, Declined, Revenue).
  • +
    Toolbar unificada: search + filter pills en el mismo card, con icono de lupa.
  • +
    Avatares con inicial del cliente en cada fila.
  • +
    Quick actions al hover (share, delete) — no más botones siempre visibles.
  • +
    Activity hint inline ("Opened 2x") en filas sent.
  • +
    Insight banner "2 estimates pendientes 3+ días" — más prominente y accionable.
  • +
    Mobile: FAB primario + mini KPIs horizontales + search con icono.

② Detail

  • +
    Layout de 2 columnas (contenido + sidebar sticky).
  • +
    Hero card con total destacado a la derecha + status pill grande.
  • +
    Action bar consolidada — primary (Email), purple (Convert), luego ghost buttons.
  • +
    Sidebar: Total card (gradient navy), Timeline de actividad, Portal link.
  • +
    Type chips por línea (Labor azul / Material verde) en lugar de badge draft gris.
  • +
    Mobile: hero gradient con total gigante, acciones primary + purple lado a lado, quick actions en cards sunken.

③ Form (New/Edit)

  • +
    Step nav horizontal desktop (antes solo había mobile wizard).
  • +
    Auto-saved indicator en el header — reduce ansiedad.
  • +
    Sidebar sticky con total en vivo + valid-until + notes.
  • +
    Line items limpios: select de tipo estilizado, input de descripción sin border, grid claro qty/rate/markup/total.
  • +
    Toggles agrupados en cards por rubro (Pricing, Payment, Delivery).
  • +
    Footer sticky con Cancel / Save draft / Save & send — jerarquía clara.

④ Print

  • +
    Header con logo box + licencia de contratista visible.
  • +
    Two-column parties block (From / Billed to) — formato factura profesional.
  • +
    Type chips por ítem (labor/material) — igual que en el detail.
  • +
    Deposit callout destacado con icono % y fondo amber.
  • +
    CTA navy "Approve online" para empujar la adopción del portal.
  • +
    QR grande + portal link mono en un footer card estructurado.

Próximos pasos sugeridos

  1. Validar dirección visual con los mocks de esta página antes de escribir código.
  2. Extender globals.css con los nuevos tokens (elevation, surface, typography scale, --wp-purple, clases .toggle, .kpi-card, .status-pill--dot).
  3. Crear componentes compartidos en src/components/: Toggle.tsx, StatusPill.tsx, KpiCard.tsx, ClientAvatar.tsx.
  4. Aplicar por vista empezando por la lista (más tráfico), luego detail, form, print.
  5. Propagar al resto del dashboard (invoices, jobs, clients, payments) reutilizando los mismos componentes.
